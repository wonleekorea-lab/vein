# 端末をまたいで日記を残す（sync）の入れ方

やることは**1回だけ、3分**。アプリ側はもうできている。

## 1. テーブルを作る（あなたの手でやる必要がある）

1. https://supabase.com/dashboard で、Sokugan と同じプロジェクト（`weanydapeersamxlphku`）を開く
2. 左の **SQL Editor** → **New query**
3. `supabase/schema.sql` の**全文**を貼って **Run**
4. `Success. No rows returned` と出れば完了

何度実行しても同じ結果になるように書いてあるので、間違えて2回押しても問題ない。

確認したいときは、同じ SQL Editor でこれを実行する。

```sql
select relname, relrowsecurity from pg_class where relname = 'vein_state';
select policyname, cmd from pg_policies where tablename = 'vein_state';
```

`relrowsecurity = true`、ポリシーが4件（select / insert / update / delete）出れば正しい。

## 2. アプリで入る

1. https://wonleekorea-lab.github.io/vein/ を開く
2. 記録の面（右）→ `···` → いちばん上の **sync**
3. **Sokugan と同じメールとパスワード**で「入る」
   （Sokugan をまだ使っていない、または別のアカウントにしたいなら「はじめて登録」）
4. 「入った。日記を合わせる」と出れば、その端末の日記が外にも残る

## 3. 2台目・入れ直したとき

同じ手順で**入るだけ**。外にあるぶんと、その端末にあるぶんが足し合わさる。
どちらかにしか無い日記は消えない。同じ日記は、**あとで触ったほう**が残る。

---

## 仕組み（Sokugan と同じ形）

| | |
|---|---|
| 置き方 | 1ユーザー1行の JSONB（`vein_state`）。日記全部で1行 |
| 衝突 | `rev` による楽観的排他。読んだときの `rev` と違えば0件更新になり、読み直してやり直す |
| マージ | サーバではやらない。クライアント側で `merge()`。同じ `id` は `updatedAt` が新しいほうを残す |
| 消したもの | 行ごと消さず、中身を落とした「消した印」（`status:'gone'`）を残す。これが無いと、消した日記が外から戻ってくる |
| 権限 | RLS で、入っている本人の行以外は読めない・書けない。未ログイン（anon）には一切触らせない |

## 鍵について

`vein-config.js` に入っているのは **anon key（公開前提の鍵）**だけ。
これが公開されていても安全なのは、RLS で「自分の行しか読み書きできない」と決めているから。
**service_role key と DB のパスワードは、絶対にここへ置かない**（RLS を迂回できてしまう）。

## 気をつけること

- **入ると、日記の本文が Supabase に載る。**それまでは端末の中だけだった。
  読めるのは入っている本人だけだが、「端末の外に出る」こと自体は変わる
- 入らなければ、これまでどおり端末の中だけで動く（sync は足すだけの機能）
- Supabase の無料枠で足りる分量（日記1人ぶんは数百KB）
